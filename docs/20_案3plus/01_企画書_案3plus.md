# 案3+「アメミチ3D」企画書（統合版）

作成日: 2026-10-17（案3+で進めることを決定）
位置づけ: 案3を主軸に、案2の流用元アプリの部品と駅出口データ、案1のシナリオ再生を取り込んだ統合版。元の3案は `../10_候補案/` にある。

## 1. 一言で

**電車が止まった雨の日、くぐらずに帰る。**
PLATEAU の3Dの街に、都営地下鉄・都営バスの路線と運行情報（ODPT）、都内159箇所のアンダーパス冠水注意箇所、内水・洪水の浸水想定を重ねる。雨量に応じて窪地から水が上がる街を見て、駅の出口から家までの「アメミチ」を自分で作って覚える。豪雨の日は、実際の運休と警戒レベルから「今くぐってはいけない場所」「出るべき出口」「待つ場所」を同じ地図に出す。道路管理者には、国交省ガイドライン（2026-10-06）の4区分の判定材料を返す。

## 2. 解く課題

2026年の豪雨では、鉄道の運転見合わせとアンダーパスの冠水が同じ1〜2時間に起きた。千葉で2人、いわき市で1人が車ごと水没して亡くなり、名古屋では地下鉄が止まる直前にアンダーパスで車が立ち往生した。

- 都内の注意箇所159箇所のうち、約3分の1（キーワード推定で54〜59箇所）は鉄道との立体交差で、駅の近くにある。
- 運行情報と冠水リスクは別々に公開されており、同じ地図で見る手段がない。
- 注意箇所リストは PDF だけで、緯度経度もバス系統との関係も無い。
- ガイドラインは区分の判断を道路管理者に委ねている。全国約3,800箇所のうち約3,700箇所は自治体管理である。

主対象は、電車が止まって車・タクシー・徒歩に切り替える帰宅者。副対象は、徒歩・自転車の通学者とベビーカー利用者、区・都の道路管理者、バス事業者。

## 4. モード

| モード | 利用者が見るもの |
| --- | --- |
| 平時「アメミチづくり」 | 自宅と最寄り駅・バス停を登録。雨量スライダーで窪地が沈む3Dの街に、注意箇所・ガード下・内水浸水想定を通らない線を引くとスコア。駅はどの出口から出るかも選ぶ |
| 平時「見てきた」 | アンダーパス付近の赤色灯・道路情報板・水位センサ・遮断機・注意喚起標示を「はい／いいえ／わからない」で報告。複数人の一致で確認済み |
| 豪雨時「いまのアメミチ」 | 先頭に運休・運行中の路線。警戒レベル、予防的規制が想定される箇所、今通れるアメミチ、出るべき出口、待つ場所（都立一時滞在施設など） |
| 管理者「区分判定ダッシュボード」 | 159箇所を冠水履歴・内水浸水想定・鉄道交差・通過バス系統数・市民確認の設備で並べ、4区分を仮判定。CSV 出力 |

設計原則: 危険箇所に近づくほど得点する仕組みは作らない。雨天・警報時はミッションと得点を止める。報告内容で報酬を変えない。「冠水している」ではなく「冠水のおそれ」と表示し、現況は道路管理者の情報と #9910 を案内する。区分は「仮判定」と明示する。

## 5. デモシナリオ（審査用）

浜松町駅・大門駅（港区）を舞台にする。大門駅は Pathways（出入口13）と、構内・屋外の両方のほこナビデータがそろう唯一の駅である。

1. 平時: 浜松町ガード下とJR川口架道橋下が窪地として出る。雨量を80mm/hにすると水で埋まる。陸橋経由のアメミチと、大門駅の出口を選ぶ。
2. 平時: 休日にガード下の設備を報告し、別の人の報告と一致して確認済みになる。
3. 豪雨時: 17時15分に浅草線・大江戸線が見合わせ。ガード下が赤く沈み、「B3 出口から出て陸橋経由」が出る。
4. 警戒レベル4: 「帰宅は推奨しない。産業貿易センター浜松町館（都立一時滞在施設）で待つ」に切り替わる。
5. 管理者: 港区内5箇所を並べ、浜松町ガード下の区分を仮判定して CSV を落とす。

## 6. 審査基準との対応

| 審査基準 | 答え |
| --- | --- |
| 社会課題解決 | 2026年の3人の死亡事故と10/6のガイドラインに、利用者側と管理者側の両方から応える |
| オープンデータ活用 | 公共交通（GTFS・shapes・RT・Pathways）× PLATEAU × 注意箇所（機械可読化）× 浸水想定 × DEM。PDF しか無かったデータを結合可能にする |
| 技術的完成度 | 事前の空間結合と出口単位の計算、PLATEAU 上の水位表現、シナリオ再生。報告基盤は稼働中のコードを移植 |
| UI/UX | 雨量スライダーで街が沈む。豪雨時は同じ地図が意味を変える |
